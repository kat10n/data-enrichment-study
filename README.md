# Обогащение данных

В курсовой сравниваем обучение на исходных данных, с ручным пополнением,
с синтетическими примерами и с обоими способами вместе.
Для текста выбрали классификацию спама, для фото — поиск животных с рамками
одного класса animal.

Пока подготовили исходные данные, сделали EDA, собрали дополнительные примеры
и разметили их вдвоём. Синтез и обучение моделей ещё впереди.

## Что лежит в репозитории

- notebooks/01_eda.ipynb — EDA исходных данных.
- notebooks/02_collection_and_annotation.ipynb — сбор новых примеров,
  запуск Label Studio, сравнение ответов и сборка итогового набора.
- data/annotation_journal.xlsx — общий журнал на 340 объектов.
  В нём источники, ответы A/B, время и итог сверки, включая исключённые кадры.
- data/real/final/ — итоговые сообщения и фото с нашей разметкой.
- data/annotated_data/ — экспорты A и B из Label Studio.
- data/real/telegram/ — таблицы источников сообщений и переводы.
- data/real/caltech/ — собранные фото и таблица источников.
- label_studio/ — задания, настройки интерфейса и связь ID с файлами.
- artifacts/annotation_comparison/adjudication_template.json — решения
  по 23 примерам после просмотра расхождений.
- docs/ — кодбук и описание расчёта согласованности.
- scripts/prepare_data.py — загрузка и подготовка базовых датасетов.
- scripts/eda_utils.py — функции, которые использует первый ноутбук.

## Данные и разметка

В базовом Telegram Spam после удаления повторов осталось 21 318 сообщений.
Для Caltech отобрали 4 000 кадров с 20 камер, поровну с животными и без них.
Камеры и серии разделили между train, validation и test.
На положительных кадрах 2 068 рамок animal.

Дополнительно собрали 200 сообщений и 140 фото. В текстовую подборку вошли
70 сообщений Telegram, 53 личных SMS и 77 переводов SMS Spam Collection.
Переводы сделаны с помощью ИИ. Каждая из нас разметила одинаковые задания
в Label Studio. Некоторые спорные фото A обсуждала с ИИ.

После сравнения ответов разобрали одно сообщение и 22 кадра.
IMG064, IMG099 и IMG117 исключили как спорные. Получилось 200 сообщений
и 137 фото с 115 рамками. Из них 71 кадр с животными и 66 пустых.

Метки текстов записаны в data/real/final/texts.jsonl.
Рамки лежат в data/real/final/photos/annotations.coco.json,
сами снимки — в data/real/final/photos/images/.
Это пополнение хранится отдельно от базовых разбиений.

## Как открыть ноутбуки

Оба ноутбука сохранены с результатами, поэтому их можно посмотреть на GitHub.
Для повторного запуска используем VS Code или Jupyter.

Второй ноутбук читает файлы этой ветки. Для его расчётов хватает стандартной
библиотеки Python. Он сверяет итоговые метки и рамки с решениями
и проверяет SHA-256 фотографий.

Первому ноутбуку нужны исходные данные EDA. Их загружает скрипт подготовки.
Исходный запуск выполнялся на Python 3.13. Из корня проекта выполните команды.

    python3.13 -m venv .venv
    .venv/bin/python -m pip install -r requirements.lock.txt
    .venv/bin/python scripts/prepare_data.py --download-images

Затем откройте notebooks/01_eda.ipynb, выберите .venv/bin/python
и выполните ячейки сверху вниз. Для загрузки понадобится интернет и около
1,7 ГБ места. Исходные данные EDA и производные таблицы создаются локально.

Используем pandas, NumPy, PyArrow, scikit-learn, Matplotlib, seaborn,
Pillow и wordcloud. Версии сохранены в requirements.lock.txt.

## Журнал разметки

data/annotation_journal.xlsx содержит по одной строке на объект, всего 340 строк.
Три исключённых кадра тоже включены, у каждого записана причина.

В таблице есть ID, источник и URL, дата обращения, лицензия, ответы A и B,
число рамок, lead_time каждого аннотатора и итоговое решение.
Для IMG021 показаны первый ответ A и исправленный статус.
Координаты рамок хранятся в исходных экспортах и итоговом COCO, пути к экспортам
указаны в журнале.

Для случаев без разногласий записано совпадение меток. У фотографий вне списка
разбора в итоговый набор взяты рамки A. Для 23 разобранных объектов решения
перенесены из JSON согласования.

Пустая дата или URL означает, что сведения не сохранились либо публичного URL
нет. Тип ссылки и пояснение записаны рядом. Значение «не установлена» в поле
лицензии отмечает отсутствие сведений об условиях использования. Даты сбора
и время получения сообщений различаются. lead_time может включать паузы.

## Label Studio и кодбук

Label Studio 1.23.2 запускали в отдельном окружении Python 3.12.
Команды установки, запуска и порядок импорта записаны во втором ноутбуке.
Задания для сообщений находятся в label_studio/01_texts/,
для фото — в label_studio/02_images/.

В docs/annotation_codebook.md сохранена рабочая схема v0.1.
Предоставленный кодбук v1.0 от 14 ноября лежит в
docs/annotation_codebook_v1.docx. Различия между правилами расчёта
в кодбуке v1.0 и фактически использованным способом отмечены во втором ноутбуке.

## Источники

База текста — [Telegram Spam](https://huggingface.co/datasets/alt-gnome/telegram-spam),
CC0-1.0. Использована ревизия af298cd351ce1d257ae789571f649d4d94d2cdd6.
База фото — [Caltech Camera Traps](https://lila.science/datasets/caltech-camera-traps),
CDLA-Permissive-1.0. Работа об этом датасете — Sara Beery, Grant Van Horn,
Pietro Perona, Recognition in Terra Incognita, ECCV 2018.

Для переводов использовали
[SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection),
CC BY 4.0. Источники дополнительных фото записаны в
data/real/caltech/sources.csv. По словам автора, 28 фото найдены вручную в интернете.
Их URL, даты обращения и лицензии не сохранились. В журнале они отмечены
как ручной отбор из интернета с неизвестными реквизитами. Для личных SMS и сообщений Telegram общая лицензия
не установлена.

При анализе учитываем, что база Telegram часто содержит технические обсуждения,
а рабочая выборка Caltech искусственно сбалансирована 50/50.
Время lead_time из Label Studio может включать паузы.
